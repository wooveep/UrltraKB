# 阅读冻结来源与 PDF 物理页

导入后的来源阅读使用成功发布修订保留的正文、页映射和图片。原始用户文件
移动或删除不会改变这些资料。新 PDF 保留从 1 开始的连续物理页序，包含空白页；
印刷页码（例如 i、ii、iii）独立显示，不用于范围定位。未提取到文字或图片的页
会明确标注，不能据此断定 PDF 的可视页面为空。

短 PDF 按保留的正文编译，长 PDF 使用 PageIndex 内容索引；新的建树输入与来源阅读
共用原生页提取，保留表格合并关系、图片顺序与软蒙版。已发布的处理指纹、索引、
原件和资产随修订保留，重编译与知识刷新复用对应输入。
DOCX、PPTX 的内部 PDF 使用同一提取；幻灯片的 `body` 直接取该页正文，
`notes` 独立关联，`all` 组合两者。备注中的 HTML 示例不会继承正文的原生表格资格。

在桌面的资料列表中选择“阅读原文”，输入 `2` 或 `1,3-5` 读取物理页，留空读取
全文。阅读窗口显示正文实际来源修订、知识修订、有效性及物理页范围。“打开冻结原件”
使用系统默认程序，适合核对原件版式。历史知识与失败更新所保留的旧正文会标出实际依据。

CLI 返回包含正文、修订和覆盖信息的 JSON：

```sh
openkb --kb-dir /path/to/kb source SOURCE_ID --pages 2-3
openkb --kb-dir /path/to/kb source SOURCE_ID \
  --knowledge-revision KNOWLEDGE_REVISION_ID --pages 3
```

API `POST /api/v1/document/source` 接受 `kb`、`hash`（来源 ID）、`view_id`、
`source_revision_id`、`knowledge_revision_id` 和可选 `pages`。`view_id` 可省略，
仅接受共享知识库的内部标识 `legacy`。无 `pages` 读取全文。
响应的 `page_range` 是实际返回的页号，`pages` 是已验证的物理总页数；请求范围内
没有记录的页在 `diagnostics` 中列出，不会凭空补正文。旧库缺少页序或处理依据时
`coverage` 为 `unknown`、物理总页数为空，保留已有页号而不猜测缺失页。

本地 PageIndex 将索引输入和图片保存在受管目录，缓存键包含原件摘要与处理策略。
全文读取和范围读取共用缓存校验与恢复。缺少页缓存时，按记录的解析器及策略从同一受管输入恢复；
图片摘要不符、原件损坏或处理策略不再可重建时会明确报错。

Markdown 原文固定为 UTF-8 Unicode 码点序列，保留换行（包括 CRLF）、空白、前言、
代码和表格。去除开头 BOM 及搬移图片引用的位置由 `origin_locators` 单独映射回原文件；
`source_spans` / `char_range` 始终指向冻结正文的 0-based 半开字符范围。
图片支持 Markdown 行内/引用式链接、HTML img src 和 base64 图；代码示例不会被改写。
未能保留的图片会列入诊断，远程图片不会自动下载。

导入建树、编译与问答共用来源资格规则，在完整冻结正文上判定结构后映射选区。
显式 Markdown 的顶层标题具有标题资格；HTML 标题还要求原生 `h1`–`h6` 位置映射。
TXT、PDF 提取文字、未声明格式的旧记录，以及代码、引文、列表和 HTML 容器里的
标题形文字不建立章节祖先。字面 `#`、图片语法或 `data:image` 示例仍是原文。
模型入口只按请求中的 typed image 载荷识别实际图片。

表格读取保留真实行列及合并关系，围栏内的表格示例不会因截取后失去围栏而被认证。
`script`、`style`、`title`、`template` 的隐藏内容不计入单元格值；无法确认的控件
内容标为未解析。部分选区保留原生位置，只有完整读取的单元格才提供完整值。
旧块包保持原字节和解析策略，阅读投影重新核验其标题、表头等来源角色。
PDF 原生表格必须有提取阶段记录的几何区域；打印出的 HTML 标签不能证明表格。
新 HTML 转换保留表格标签、合并属性、控件和段落边界，复用同一单元格规则。
`input`、`select` 等未支持的控件即使完整读取也不提供已确认值；
真实空值、值未确认和部分读取分别保留。两个段落的 `1`、`2` 不会拼成 `12`。
编译响应的路径转写校验也消费同一来源投影：只有已解析、完整读取的单元格
提供可转写的可见值，不对裸正文再次解释 HTML 或解码实体，不跨行拼接路径。
短文、分段摘要、概念／实体生成及页面更新采用相同规则；复用已接受响应时也会校验。
缺少结构证明的旧正文仍可精确摘录，不凭打印标签补认证，不改写保存的缓存。

图片资产可用不代表图片出现在当前选区。图片出现位置使用提取阶段记录的字符范围，
只给已读到该出现位置的选区关联图片；同一路径的字面示例不建立关联或原文图注。
原文图注须有明确来源记录。旧页没有出现位置时，全文仍提供页级资产清单，
部分选区不凭路径补图片，并标出位置未确认。幻灯片投影不会通过元数据带回未选分区的正文。
裸旧 Markdown 未声明格式时不补图片角色，不因字面 `data:image` 示例触发重处理；
已保存的原图画廊与资产仍保留。生成的图片引用不能充当原文导航锚点。

文本度量固定使用离线 tiktoken 0.13.0 / cl100k_base：5,000 tokens 及以下为短文，
与执行模型无关。`tokens` 和 `characters` 显示完整冻结文本的大小，`pages` 为空。
首次编译失败时仍可阅读已保留的规范化正文，`knowledge_revision_id` 为空且状态保留失败原因。
已有成功正文时继续显示该正文及其度量，失败的新目标另列 `target_processing`。

```sh
openkb --kb-dir /path/to/kb source SOURCE_ID --chars 0:120
```

API 对应可选字段为 `chars: "0:120"`；桌面原文窗口提供相同范围输入。
问答来源工具 `get_text_content` 返回相同字符范围和原文件映射，且受所选知识快照的证据范围限制。
重编译复用冻结输入和分类；watch 对本地图片的更改和缺失状态也生成新的内容修订。
