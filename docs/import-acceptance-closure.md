# 导入验收关闭记录

2026-09-15，维护者确认以下验收修订，优先于 #23/#34/#45 和旧修复计划中冲突的
关闭门槛。这是接受已有交付与已登记限制，不是将历史语义失败改为通过。

## 当前门槛

> 保留关键事实与来源保护，允许明确遗漏。普通文档处理异常不阻断正常流程，
> 完成已分析且正确内容的发布。接受问答拒答或知识遗漏，资料正常发布、原件可读、
> 缺失可见，用户后续可以手动编辑知识。

- 普通解析、OCR、附件、提取、规划、生成和核验问题，有限恢复后作为内容缺失。
  已有可靠内容继续发布，其他文件继续；不要求用户先修复或逐项确认缺失。
- 全部候选被排除时，原件可靠保存后仍完成资料登记和可编辑的缺失入口，明确知识
  为 0；不伪造知识页，不将处理完成称为原文完整覆盖。问答拒答不回滚已发布资料。
- 保留关键事实、必要条件及来源核验，缺失前提会使依赖操作变义时一并排除。
  不能通过取消核验、虚构引用或故意放行已检出的错误完成验收。
- 原件、来源/版本身份、历史引用、其他来源贡献和人工修改保护保持。用户停止、
  执行硬额度及无法保证身份、保存或事务提交的故障仍如实报告；未保存不能报发布
  成功。远端作业状态不明不盲目重发，普通内容错误不升级为全局失败。
- 少量已登记的模型语义问题接受为已知限制，用户可手工编辑，转 [跟踪已登记的模型语义误判与标题译义问题（#47）](https://github.com/wooveep/UrltraKB/issues/47)。
  有来源支持的冗余表达转 [改进问答中的冗余表达和技术性附加说明（#48）](https://github.com/wooveep/UrltraKB/issues/48)。两项不作为本批关闭依赖；新发现的
  正常发布或来源保护回归仍应修复，不能借此笼统豁免。

## 不再作为本批关闭条件

不要求新的独立小样本完整通过，不要求补做有效冷配对或证明性能收益，不要求重新
全量导入旧大文档或全部 OCR，也不指定标题/正文分项核验为必须完成的实现。
成本全部列报，不作为关闭门槛；执行额度仍为硬上限，不因关闭重置。

历史独立样本失败仍保留，开发后复测只算回归，人工修改不冒充自动语义通过。
诊断候选与实际知识/完成答案分开；未上线的两种标题核验诊断不宣称已实现。
性能收益仍须同能力、同覆盖、同质量的有效证据支持；当前完整有效等价组不足，
结论是不可比/未证明提速。#34 原验收允许报告无性能结论，后续计划另将对照齐全
列为关闭门槛；本次维护者明确取消该门槛，直接关闭 #34。
