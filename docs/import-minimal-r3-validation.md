# 小文件导入修复与真实验证第三轮

日期：2026-09-14。延续 [修复计划](import-repair-plan.md) 和
[第二轮记录](import-minimal-r2-validation.md)。本轮继续修复通用代码、提示和协议，
没有按文件名、品牌、原文数值或预期答案做分支，也没有手改验证库知识提高自动质量成绩。

普通解析、OCR、提取、规划、生成和核验异常允许形成内容缺失；可靠部分或零知识入口
仍正常登记发布，用户后续可编辑。问答不通过不会回滚导入。用户停止、硬额度、存储、
身份、事务及真实人工覆盖保护继续有效。

## 授权与复现

本轮授权上限为 80,000,000 tokens、2,000 次物理模型请求、5 小时、100 页次云 OCR。
起点 05:32:30 UTC，截止 10:32:30 UTC。失败、输出截断、格式恢复、分批核验和语义修正
都计入原请求账本；未知用量使用保守预留。OCR POST 页次与查询/下载 HTTP 次数分开。
额度是上限，不是消费目标；旧轮支出没有重置。

完整证据位于 `examples/kb/Ocloudware/outputs/issue46-minimal-r3-2026-09-14/`。
`authorization.json`、各版 manifest、`bindings.json`、`code/*-hashes.json` 固定额度、
输入、角色、来源和代码；`runs/`、`requests/`、`ocr-requests/` 保存操作意图、实际配置、
请求、返回、发布结果和原文回读。运行前校验输入 SHA-256，实际业务代码来自 Git 归档。
计量探针仅记录实际传输，并在派发前检查额度；凭据不进入提交或公共 issue。

沿用前轮模型、增强能力和冷导入/问答配置；依赖分发清单另存于
`runtime-distributions.json`。物理模型回执包含提供方缓存及 reasoning 用量，后者不重复
加到总 tokens。流式响应为计量而缓冲，不能据此比较首字时间。

原有五文件全部保留。两份新文件在首次调用前固定内容、问题及锚点并检查版面：
一页扫描 PDF 74,826 B、一页无图片 DOCX 37,295 B，语义与原五文件不同。
DOCX 的首次编译问题后来参与修复，其后只记回归；PDF 的云端拒绝、pending 和恢复
分别保留，不能以有图片或正常发布代替 OCR/语义通过。

## 真实结果的判断边界

机械完成、链接有效、原文语义和自动知识覆盖分别核对。
`semantic-findings.json` 保存逐项判断及对应运行；`answer-link-audit.json` 检查已完成
答案的文件/锚点和未展开标记，不把链接存在当作语义支持。

- `bounded` 冻结版五格式均正常冷发布，一问一追问完成，普通复导均零请求。PDF
  保留原始组织标签，未再写成实体的独立属性；DOCX 答案仍曾误归阅读器注解。
- `compact` 去重/身份编码后，小表首问及追问、PDF 首问完成；DOCX 首问与 PDF
  追问的协议失败保留。原始回执重放证明：正确坐标数组原先被标量协议拒绝；
  错误覆盖状态路径在修复后仍不能通过。
- `adaptive` DOCX 首问及追问机械完成，但保留了带 `@` 的未展开引用。其后
  `citations` 同来源回归完成，两条最终答案均使用可回读的完整引用；旧错误未覆盖。
- `adaptive` PDF 修复原有范围后，后续有效核验又拒绝了未经充分支持的版面描述，
  因有限语义修正额度结束而失败。截断拆分有效不等于最终语义全对。
- 新独立 DOCX 的首问保留全部三行、前提和否定条件，追问保留时间限制、只读及
  归还义务；但知识页存在注解归属错误，因此不能判整个文档独立通过。
- 新扫描 PDF 首次云队列拒绝时，正常发布零知识入口，普通复导零模型请求。
  显式 Continue 后作业受理，在本地等待上限内仍为 pending；继续正常保留缺失和
  作业身份，不盲目再次上传已受理页面。

## 历史 B1 与修复后对照

B0 仍为 `b4c7ce3`，历史数据库 B1 仍为 `c04d8be`，均不修改、重命名或补当前代码。
离线公开入口行为探针禁止非本地网络，证明历史 B1 的空内容和全部候选排除返回
unfinished；修复版正常 added/completed，随后独立文件仍能发布。这是能力差异，
不是可以从成本中剔除的“额外开销”。

本轮另冻结明确命名的 **B1-R3 候选对照 `26f492e`**，原生空库完成相同五个小文件的

变化的起点，不能证明更早优化的贡献，也不替代原 B0。`B1R3-role.json` 和 Git 差异
记录其与历史 B1 的区别。失败及受限覆盖单列，不能默认五例全部质量等价。

原文全部行证明已生成知识覆盖相等。
`baseline-equivalence-matrix.json` 按五例记录这些限制；B1-R3 与最终代码仅在三个受控

五行知识也不构成同覆盖配对。`B1R3-role.json` 已补充候选对照未通过的实际结论。

身份编码的离线投影对 16 个真实核验请求精确往返，预计输入 tokens 减少约 20%–36%。
这是输入投影，不能当作整个问答或冷导入的实际节省。分批、纠错及 reasoning 仍有
显著开销；本轮不据单次运行宣称提速，也不追加三组重复运行刷性能成绩。

原逐例历史累计 tokens/B0≤1.10 尚未满足。仅原小文本已有候选开发导入支出至少
45,759 tokens，已超过其 B0 26,649 的 1.10 倍；后续代码优化只能减少新增费用，不能
降低已发生的历史累计值。该数字不把未知用量补零，也不将问答或基线运行混成一次冷导入。
在维护者明确修订之前，继续按原门槛保留未通过状态。
