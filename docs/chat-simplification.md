# 精简问答流程

## 目标与依据

普通问答回到按需查资料后直接回答的时延水平。当前版本在草稿生成后强制逐段
调用 LLM 核对，修正后再次全文核对。已记录的专项问题在 50.9 秒生成草稿后，
继续核对和修正至 744.5 秒仍未完成；这不是最初版本的公平性能对比，但足以
定位草稿之后的额外等待。

## 执行方案

1. 一个主 Agent 保存问题、会话历史和工具结果，负责资料选择与最终回答。
   资料选择属于原有工具调用循环，不额外增加一次规划模型调用。
2. 增加批量原文搜索和范围读取，每批至多 4 个独立操作，并发读取已经固定的
   原文快照。采用线程处理只读操作，避免 Windows 多进程启动、复制大段上下文
   和重复建立模型客户端。每个结果保留其请求、来源、版本、位置与原文引用。
3. 删除默认回答后的独立语义审校和局部修改/全文重审循环。仅执行本地引用
   标识展开、引用目标检查与输出完整性检查；最多一次必要的完整回答补救。
4. 缩短主回答提示词，要求先回答用户问题，保留步骤顺序、适用场景、删除/禁用
   操作及例外。有明确原文依据后停止扩展相邻章节；缺失信息如实说明。
5. 保留圆角消息卡片、公开步骤和耗时反馈。完成的回答仍通过同一会话入口保存，
   后续提问继续使用主 Agent 的原始上下文。资料编译和发布的核验规则不受此方案影响。

## 验证

- 请求数回归：一次读取加一次生成即能完成和保存，不触发额外审校请求；覆盖
  对话、单次问答和终端入口。核对服务不可用不得影响普通回答。
- 并发回归：独立读取确实重叠运行、返回顺序稳定、引用与来源绑定不混用，
  单项失败可定位，取消仍有效。批量工具只允许读取，不接受写入指令。
- 保留引用、截断、会话保存/追问、任务取消和图片能力相关检查。
- 使用真实知识库副本进行完整新问题测试，记录总耗时、资料读取轮次、模型请求
  数和答案。专项问题须包含自动分区、删除 swap 及原文对应的空间分配条件；
  另测宽泛问法，避免只对提示中已经包含答案的问法有效。
- 性能结论区分离线请求数测试与真实模型耗时；只读快照准备、模型服务时延和
  文档复杂度仍计入完整问答，不用失败点续跑代替全程测试。
