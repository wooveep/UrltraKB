# 图片、图注与批注的导入上下文

原文段落及其引用位置继续分别保存。为模型组合上下文，不通过无差别合并段落来改变事实的归属。

## 批注和脚注

DOCX 的批注、脚注、尾注在解析时已插入引用它们的正文段落。除原有显示标记外，现在还保留 `inline_annotations`，分别声明 `editorial_comment`、`footnote`、`endnote`。这些身份随抽取、生成和审核一起传递。生成稿使用批注内容时应保留“原文批注”等归属，不能将批注悄悄升级为正文操作要求。

## 图片与图注

图片原件、显示图和 OCR 输出已有可追溯的资产关系。对同一结构范围内、有明确“如下／下图／上图”等指向的相邻图注，现在把图注与连续图片组的完整文本、图片链接、OCR 内容一起作为上下文传递。超过请求预算仍走已有预算处理，不把截断窗口伪装成完整图片内容。普通相邻文字不自动变成图注，也不跨章节或表格单元格绑定。

提示词要求保留图注时同时保留相应图片，在 `【图片】` 段中组织原图链接及可用 OCR。模型仍需遵守引用和发布校验；这项输入修复不保证所有模型都会正确组织输出，也不等于已经重新验收了先前未发布的主题。

展示时应区分：

```text
【图片】
原文图注：……
图片：实际保存的原图／显示图链接
OCR：可用的文字识别结果
图片理解：可用的视觉观察，保留其推断身份
```

只有实际存在的字段才可输出。原生正文、OCR 转写和视觉观察不能混称为逐字原文。当前导入阶段已有图片 OCR；独立图片理解主要供问答按需调用，本次没有新增导入阶段的自动视觉请求或将视觉观察冒充原文。要支持导入时自动视觉补充，还需要接入独立的观察记录、预算、失败恢复及编译证据协议。

## 低像素图片

用户选定的共同阈值是：**长边小于 256 像素，或总像素少于 16,000**。按原始实际像素判断，不按 DPI 标签或页面显示尺寸判断。满足条件时不发起 OCR 或图片理解请求，保留原图、图注和跳过记录。图片理解的裁剪区域也必须满足该阈值；显式连接测试使用的内置测试图不受资料过滤影响。

OCR 还沿用原有的窄条、图标及平色图过滤。阈值不是可读性保证，跳过也不代表图片不含重要信息。资料中的必要信息无法核实时仍需保留覆盖限制。

## 审核与纠错

可以用短提示词明确检查对象，并分别配置 low 与 high。应保留原文、候选内容、必要上下文、精确差异和输出协议，削减重复说明；纠错只处理已经定位的问题，修复后仍审核。

此前四项固定审核样本中，第二版精简提示词配 low 和 high 均判对 4 项，但耗时分别为 155.7 秒和 193.1 秒；现行 high 为 92.9 秒、判对 2 项。无推理档位有漏检。样本很少且参与过调优，不能证明精简加 low 已实现质量相同的提速。因此本次保留已有审核、纠错配置，不自动降低推理档位或宣称新策略已经通过验收。
