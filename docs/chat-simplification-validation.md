# 问答精简验证

## 改动

普通问答和对话使用一个主 Agent，资料选择与生成沿用同一会话上下文。
新增 `search_sources`、`read_source_nodes`，每批最多四个并发只读操作。
原文快照、来源身份、分页位置与引用在每项结果中保留；不增加独立的规划
或汇总模型调用。

删除默认逐段 LLM 核对、核对协议恢复和局部修正后全文重审的实现及其专属测试。
保留本地引用展开与目标检查、输出完整性检查、会话保存和取消。输出截断、
空回答或引用错误合计最多补救一次。新的请求数与会话测试取代原有强制审校策略测试。
资料接入、编译与知识发布的核验逻辑没有改动。

## 请求数与功能验证

- 修改前，读取加生成的两次请求预算在对话、单次问答、普通终端和流式终端四个
  入口均因还要核对而失败；修改后四个入口均完成。该测试直接经过真实模型协议
  适配层和应用入口，模型响应由本地服务提供。
- 两份资料的读取在独立线程中实际重叠，按请求顺序返回，来源和原文内容没有混用。
- 批量搜索/读取的短引用可以展开、保存，并在同一会话的追问中继续使用。
- 超出批量数量/内容预算会拒绝执行；单项资料错误单独返回；任务取消和处理中断
  传回主任务，原始线程上下文得到保留。
- 截断、引用补救、空回答、追问保存、公开步骤、圆角卡片和图片功能分别验证。

## Windows 真实模型记录

使用 `cloudyiKB` 的现有私有副本、已配置模型与凭据，问题从新的会话开始执行，
没有复用之前捕获的模型响应。完整耗时包含快照准备、查资料、生成和保存。

最初的精简提示词下，两条问题分别在 24.61 秒（宽泛安装分区问题，5 次请求）和
22.14 秒（自动分区/swap 专项问题，6 次请求）完成并保存。两条答案都包含自动分区、
删除 swap、把释放空间加到 `/home`，并单列多盘手动分区不创建 swap 的条件。
后续同一精简提示词的宽泛问题在 66.78 秒完成，说明服务时延和检索轮次仍会波动。

中间另试了更强调部署范围、压缩展示的提示词，出现模型扩大检索范围和服务返回
`InternalServerError` 的情况；该提示词调整已撤回。服务返回只有通用 500 错误，
无法据此确定是输入规模还是服务内部原因，不把这些失败计入成功验收。

这些记录证明默认问答已经不再支付逐段审校的额外请求成本，不是与 9 月 7 日
历史程序进行的严格 A/B 性能实验，也不保证所有问题有固定的秒数。

本地完整记录保存在 `build/chat-simplification-*`，原始知识库和原失败会话未改写。
