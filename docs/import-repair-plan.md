## 首要原则

> 允许文档导入存在异常，但不要因此中断、中止或退出正常发布。
> 内容可以缺失，用户后续可以手动编辑知识调整。验证使用小文件完成最小闭环。

普通解析、OCR、附件、提取、生成及核验问题，在有限恢复后作为内容缺失处理。
已有可靠内容正常发布，其他文件继续；用户不必先修复或逐项确认缺失。
错误候选可以排除，但其失败不能成为其他知识发布的前置门槛。
缺失前提会使某段操作变义时，一起排除该段操作，继续独立内容。

本次进一步明确边界：原件已可靠保存，但本次没有可生成知识时，也应完成资料登记，
提供可编辑的来源/缺失说明入口，显示“导入完成，有内容缺失；生成知识 0 条”。
不生成虚假的知识页，不把 0 条知识或 OCR 转写称作完整分析。
P0 已取消全候选排除时提前返回未完成的门槛，零知识与部分知识走相同发布事务。

原件、版本、引用历史和其他来源贡献保留；用户补写内容沿用既有人工编辑保护。
普通复导不覆盖人工内容、不重新抽取已完成部分；显式继续处理缺口及受影响依赖。
只有用户停止、硬额度、身份/存储/事务无法保证等执行约束才允许停止相应执行。
远端状态不明的工作不得盲目重发，其本地缺失状态与其他独立内容的发布分别处理。

发布结果与覆盖分开：正常提交可以带 `omissions`、警告及 `coverage=partial`；
旧记录无法核对时保持 unknown。问答未通过不能回滚已导入资料，
用户手工补写也不能自动将原件 OCR 或分析覆盖改成 complete。

## 执行顺序与具体交付

### P0-1：让内容耗尽走正常登记与发布收尾（#46）

- 在现有事实、规划、生成、依赖检查和文档应用流程中统一普通内容遗漏结果。
  将“所有候选被排除”与身份、事务、用户停止、全局预算故障分开，不能笼统捕获后者。
- 删除依赖“必须有一个成功主题”才能登记来源的内容门槛。没有知识时，事务仅提交
  来源入口、缺失说明和发布登记；有知识时同一事务提交可靠知识及缺失说明。
- 更新旧版本时不得把旧知识假装成本次新内容；按来源贡献规则撤回失效自动内容，
  历史引用仍可读，其他来源与人工补写继续受保护。
- 主要范围：`agent/evidence_compiler.py`、`evidence_facts.py`、`evidence_dependencies.py`、
  `application/document_pipeline.py`、`knowledge_commit.py` 和结果状态映射。
- **最小验收**：两段独立内容，一段失败另一段发布；全部提取/生成/依赖候选被排除时
  导入完成、知识为 0、缺失可见、来源可打开；随后同批正常文件仍完成。
  坏原文、未知模型返回不被编造成事实；旧版及人工内容保护仍通过。

### P0-2：缺失后的编辑、复导与继续形成闭环（#46、#13）

- 复用现有知识编辑入口；从导入结果打开已发布知识或零知识资料入口，查看缺失原因。
  用户补写不需要先执行 OCR 或再次导入，缺失诊断不作为编辑阻塞条件。
- 普通同版本复导复用已完成登记，不再因缺失重新计费；显式 Continue 才处理有效缺口。
  用户补写与自动生成区分，后续继续/更新不得静默覆盖。
- 单页 OCR 错误、队列拒绝、传输中断、图片不可识别分别记为局部缺失。
  已受理作业沿原身份查询；执行状态不明时不重复 POST，其他独立内容继续。
- **最小验收**：1 张图加 2 段文字，图失败仍发布文字；编辑补写→普通复导→Continue，
  人工文字、旧引用保留，已受理 OCR 不重复提交。CLI 返回 0、REST 与桌面显示完成加缺失。
  用户停止与硬额度仍停止新请求，不能通过“容错”继续消费。

### P1：减少回答中的机械引用错误和修正副作用（#46 回归、#45 验收）

- 工具返回短证据标识，程序将其映射到完整来源链接并渲染路径和锚点。
  模型只选择本次实际观察的标识；未知或歧义标识不能模糊匹配、猜测修正为合法引用。
  兼容现有有效引用；不再要求模型反复手写长哈希路径。沿用现有工具和渲染入口。
- 引用存在和语义支持分别校验。表格按表头、同行条件核对；术语名称不补成用途/别名；
  未完整读取不能断言全文没有某项内容；图注明确位置才建立左右对应关系。
- 语义修正用可定位单元替换，程序保留未受影响单元和证据绑定；跨单元改动时
  明确受影响范围并重核。保留原文条件，检查章节引用；沿用有限修正次数和总预算。
  已实现受影响单元 ID、限定 JSON 修正与完整重核；后续引用修正同样受原范围约束。
- **最小验收**：6 行表含一条不同条件、两段条件说明和两幅带图注示意图；
  各一条问题加一条追问。无坏链接、无额外分类、无遗漏已读必要条件、图示不互换。
  受控 HTTP 服务覆盖错误返回；真实用例失败保留诊断，不重复判定直到通过。
  回答质量检查不进入导入发布的阻塞路径。

### P2：固定小文件完成真实导入与编辑闭环（#13、#45）

先冻结下面的脱敏小样本及原件锚点；每个文件只覆盖必要结构，避免大文件重复校准。

| 样本 | 上限与内容 | 观察重点 |
|---|---|---|
| Markdown/文本 | 2 KB，3 段含前提、否定和例外 | 部分/全部遗漏，独立内容继续，编辑保护 |
| PDF | 2 页，1 页原生文字、1 页扫描文字/带左右图注示意图 | 云 OCR、页码与图示对应，单页失败不阻断 |
| DOCX | 2 页，2 个标题、1 个小表、1 张内嵌图 | 原文位置、图像转写、缺失后的人工补写 |
| XLSX | 1 表，6 行数据加表头 | 条件不同的相邻行、完整枚举、无用途臆测 |
| PPTX | 2 页，文本和 2 个可定位对象 | 幻灯片顺序、对象绑定、原文回读 |

每种格式最初只做一次冷导入、一条问答和一条追问；另选一例做普通复导与一次 Continue。
纯故障组合用受控服务的小样本完成，不把所有故障都变成真实 API 实验。
云 OCR 的正常采纳和恢复最多用上述 PDF 与 DOCX 的 3 个单页输入；图片理解未启用时
保持缺失，不为关闭导入票强行补齐视觉识别。图示问答只使用有明确图注/位置的证据。

固定输入、预期保留与允许缺失的锚点、模型选项、初始状态和输出预算；首轮失败后
先修改通用代码或提示，再对该最小案例复测。不得更换样本或手改知识来抹掉失败。
在这五个文件内预先固定角色：文本、DOCX、XLSX 用于校准，PDF、PPTX 用于独立验证；
两组使用不同语义内容，同系列或同内容的格式副本不能跨组。独立组在代码与提示冻结后
再运行；一旦根据其失败调参，后续复测只记回归，不继续冒称独立验证。
没有有效独立结果时，#45 的对应条件保持未通过；不自动增加文件或付费运行。
正常人工编辑另列为功能步骤，不计入自动生成质量通过记录。
原有 23 份和长文记录留作历史兼容/压力证据，不再要求重新全量导入后才关闭这些票。
小文件通过不推广为长文吞吐、完整 OCR 或普遍模型准确率结论。
