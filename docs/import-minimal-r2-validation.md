## 授权、输入与复现

本轮单独授权上限为 **80,000,000 tokens、2,000 次物理模型请求、5 小时、100 页次云 OCR**。
起点为 2026-09-14 04:00:01 UTC，截止 09:00:01 UTC。额度是上限，不是消费目标。
模型重试、失败、核验、纠正都计费入账；云 OCR 的 POST 页次与查询/下载 HTTP 次数分别记录。
未知用量使用保守预留，不算零。历史轮不重置，也不拿剩余 tokens 抵消请求或时间上限。

原件仍为 `examples/docs/issue46-minimal/` 中预先冻结的五份文件：文本 249 B、
DOCX 14,772 B、XLSX 5,043 B、两页 PDF 36,327 B、两页 PPTX 29,388 B。
本轮没有更换失败样本、扩大到长文或修改原件锚点。文本/DOCX/XLSX 是校准组；
PDF/PPTX 最初是语义不同的独立组。两者的失败后来用于修复，后续仅记回归，不能再算独立验证。
清单中的文本“重试”锚点笔误另记勘误，实际按原文“重启”核对，原件未改。

验证目录：`examples/kb/Ocloudware/outputs/issue46-minimal-r2-2026-09-14/`。
`authorization.json`、`manifest.json`、`bindings.json` 保存额度、输入和来源绑定；
`code/` 保存各冻结提交和文件哈希；`runs/` 保存每次意图、有效配置、事件、结果与回读；
`requests/`、`ocr-requests/` 保留每个实际外部请求和返回；`run-summary.json`、
`ledger-summary.json` 汇总消费；凭据只保存在本地私有配置，不进入报告或 GitHub。

通过原应用入口初始化空库、导入、Continue、重新解析、问答和人工编辑。
真实业务代码来自相应 `git archive`，没有给 B0/B1 补当前业务逻辑。
计量探针只包裹实际传输，记录请求前预留与返回用量；流式响应为核对用量而缓冲，
因此本轮不能用于首字时间或流式体验比较。原 runner 及后续增量均归档并在运行意图中记录哈希。

业务模型配置为 `deepseek/deepseek-v4-flash`，返回模型名 `deepseek-flash`。
冷导入初始上下文/输出为 32,768/8,192，问答为 65,536/16,384；最大上下文/输出
131,072/32,768，单操作最多 200 请求和 1,000 万 tokens，外层总账继续约束整轮。
编译关闭 thinking，核验开启 low，仲裁开启 high；未将 reasoning tokens 再加到已包含它们的输出总数。
云 OCR 使用用户指定的 PaddleOCR-VL-1.6 jobs API，单次只提交物理单页，方向识别及去弯曲关闭。
配置、依赖分发清单、`pyproject.toml` 和 `uv.lock` 均保存；三方依赖文件在各业务快照间相同。

人工补写单列为编辑功能测试，未用于提高自动质量成绩。

| 提交 | 问题与修复 |

| `5a6c14b` | 可选 OCR 历史中的坏版本记录不阻断原文读取；完整核对作业身份、页面、配置和回执状态，不能凭任意 job_id 宣称已受理。 |
| `c09e20f` | 核验逐字引用短元数据片段，不能重组 JSON；忠实翻译不要求原文同时包含译文，但不得增加含义。回答只说明影响当前问题的缺失，避免未请求的内部计数。 |
| `b47d7b3` | 事实提取、生成及核验区分文档组织标签与实体属性，检查小标题。真实标题断言仍保留；标签不能因被原样引用就成为“设备具备某属性”的依据。 |

OCR 定位根因有完整原始响应佐证：云端返回 960×1200 像素的二维块位置，原 PDF 为
480×600 points。原装配器只保留了文本/图片，没有保留块位置。修复后直接用已经下载的
结果重装配，六个版面块获得物理第 2 页坐标，**没有新增模型请求或 OCR HTTP 请求**。
新 `display_bbox` 对旋转页面使用显示方向，避免把未旋转坐标误当成左右位置。
原始尺寸、预处理和块坐标的契约参照
[PaddleX 官方 PaddleOCR-VL 文档](https://paddlepaddle.github.io/PaddleX/3.7/en/pipeline_usage/tutorials/ocr_pipelines/PaddleOCR-VL.html)。

问答读取 OCR 状态是读取保留回执，不是实时查询服务。一次明确的 `cloud_queue_full`
拒绝不代表仍在排队；已下载结果不代表图片理解已启用，也不代表全部知识已提取。
不完整或无绑定的旧回执只能显示 unknown/unavailable。受理状态不明的请求仍不盲目重发。

## 发布与内容覆盖

`699f5f3` 冻结版在原生空验证库完成五种格式冷导入，均为正常发布。
旧轮保存的 PDF/PPTX 也通过 Continue 完成发布；解析与原文回读、生成知识分别核对。

| 格式 | 自动发布及保留内容 | 缺失和限制 |
|---|---|---|
| 文本 | 保持时间、先停止、认证失败不重启、维护例外均保留 | 不把含糊的保持动作扩写成特定技术机制 |
| DOCX | 正文和表格在云 OCR 队列拒绝时仍发布；之后显式 Continue 取回正式 OCR | 该次 Continue 的生成主题因缺少必要上下文被排除，仍正常提交零知识资料入口、原文及缺失说明；不是完整知识提取 |
| XLSX | 六行值、类型及特殊行条件保留，29 个原文块可回读 | 首行表头角色在解析元数据中未确认；不能由此断言原文没有表头，也不能假称已验证角色 |
| PDF | 原生文本及扫描页 OCR 保留；左右图注、独立图形和物理页位置可回读 | 生成中被排除的独立主题明示遗漏；原文仍能支持问答，不把生成缺口当成原文不存在 |
| PPTX | 六个原文块、稳态前提、时间窗口、夜间路由及否定例外保留 | 首轮把组织标题误解成属性，后续 Continue 已去掉该扩写；这是回归修复，不是独立首轮通过 |

DOCX 作业历史包含三次明确受理前拒绝，之后一次显式 Continue 提交被受理并下载。
PDF 的已受理作业沿原身份复用；坐标修复及后续编译没有重新上传已受理页面。
对原版本/解析的引用继续读回，不用最新解析悄悄替换历史证据。

人工编辑分两条记录：旧轮已编辑资料在新代码拟改写时触发保护提案，没有擅自接受；
同一冻结编译配置下的人工编辑、普通复导和 Continue 保留了人工页面完整版本且零模型请求。
本轮还通过应用编辑入口补写零知识资料摘要，后续升级重编译与普通同配置复导分别记账。
编译契约升级导致的重新计算不能冒充“同配置复导”，人工编辑结果不计入自动知识质量。

覆盖差异，不能据此伪造同质量比值，也不能用文本节省抵消其他案例。
只有未来确需声明速度收益且质量可比，才追加三组成对观察；本轮没有为此刷重复冷运行。

实际热点由完整请求 payload 的阶段归属核对，保存在 `cold-physical-phase-costs.json`：
小表核验 85,789 tokens，占冷导入 66.57%；PDF 核验 65,285 tokens，占 59.14%。
外层预算的阶段名称有父阶段聚合，不能将其所有 `generation` 条目误称纯生成。
长证据元数据、重复上下文、纠正与核验 reasoning 是后续优化重点；提供方缓存不能减少
本规格统计的实际输入 tokens，取消核验或减少必要知识也不能用来达标。
