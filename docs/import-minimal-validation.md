## 发现与通用修复

1. DOCX 追问的核验定位了原文不支持的否定断言，但有效修正省略空 `insertions`
   时被协议拒绝。`984cc5d` 允许省略空操作列表，仍拒绝 null、未知字段、空对象、
   越界单元和整段重写，并要求修正后的完整答案重新核验。真实复测的新答案无需
   修正即完成，因此协议路径的证据来自受控回归，不能把新答案通过当作路径命中。
2. 真实 Continue 重新看到自身发布的目录，导致已完成规划改名并重复生成。
   `f038b6c`、`a88618c`、`5643e69` 保存来源绑定的已完成规划成员，继续只处理剩余成员；
   新主题或无关页面加入时可复用原不可变核验回执，正文实际链接失效则重新生成。
   检查包含双括号、普通 Markdown 相对/引用式及 HTML 链接，代码与外链不误判。
   当前事实、其他来源贡献、schema、模型与规则变化仍使相关复用失效。
3. 复核发现单个主题超出请求容量时，尾部完整性判断仍可能阻断发布。已改为保存
   已完成成员并记录遗漏，其他内容及零知识来源入口仍经正常事务发布。
4. XLSX 冷导入出现表头、行值与行关系重复主题，成本仍需优化；问答核验输出
   截断通过明确提高该实验配置解决，未改成不核验。该费用未从累计账本剔除。

生产逻辑没有案例名称、品牌、固定原句或答案特判。自动输出检查先完成，之后才
通过公开编辑入口补写一个人工段落，独立验证普通复导及预算停止的 Continue 后
原页字节保留；人工段落未计入自动质量。准备清单有一处将原文“重启”误写成
“重试”，审计按未修改原件判定并记录纠正，没有反向修改原文配合预期。
