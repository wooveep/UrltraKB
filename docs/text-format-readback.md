# TXT / CSV 的冻结与来源读取

TXT、CSV 与 Markdown 使用同一来源接入、知识版本发布、固定 token 分类、
内容块索引和编译流程。原件、编码决定及诊断在格式解析前作为 SourceRevision
保存；CSV 解析失败不会丢失已经判断出的编码，也不会发布空知识。

编码策略先按 BOM 判断 UTF-8/16/32，再尝试严格 UTF-8，最后使用已固定的
`charset-normalizer==3.4.7`。推断编码明确标记为 inferred，保存 chaos/coherence
和核对提示；不以替换字符吞掉解码错误，拒绝二进制 NUL。该包原已在锁文件中，
本次因直接调用提升为直接依赖，保留版本、来源及哈希；已核对随包 MIT 许可证。

TXT 保留正文、前言、长行、Unicode 与 CR/LF，不抓取文字里的图片表达式。
BOM 从规范化正文移除，但原件位置映射包含它。桌面以字面文本显示 TXT，
显示用围栏不写回冻结正文、不改变字符位置。

CSV 使用 Python 标准库 `csv.reader` 的严格 Excel/comma dialect；没有业务
类型推断，前导零、公式样式字符串、日期文本和空字符串均为字符串。第一条
记录也作为数据保存，不推断为业务表头。为 Markdown 显示生成 Column 1…列名，
这些列名、空格、分隔符不是可引用的原文锚点。换行和特殊字符经过可追溯的
显示转义；每个单元格保存原始记录号、列号、物理行范围及完整字符串值。
行列号从 1 开始；字符坐标是解码原件/规范化正文各自的 Unicode 码点半开区间。

不规则记录保留实际列数，不按最大列数补齐持久化空单元格。超大单元格按共同
块规则细分，表头补充单独记录；跨块范围只返回位置及选中正文，不重复整格值。
需要完整值时读取全文，局部元数据用 `value_complete=false` 明确标识。真正的
空字段仍有零长度位置与空字符串值，与缺少字段、空物理记录区分。

CLI `source --chars START:END` / `--blocks 1,3`、REST 来源接口和桌面共享这些
范围与编码元数据；精确资料修订读取不重新访问原位置文件。监听只接收 raw
输入，规范化正文、映射和块包保存在受管目录，不构成新来源。

自动验证使用小型实际文件、真实解析/接入/发布/回读，仅替换外部模型。真实
模型质量与发行包平台验收仍需对应人工验收议题确认。
