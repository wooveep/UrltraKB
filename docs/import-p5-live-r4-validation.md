## 真实缺陷与结果解释

1. **阅读器说明污染知识。** 早期 DOCX Continue 将首行未确认等状态写进知识；候选核验
   也曾错误接受。v13/角色规则修复后，相关错误候选可排除，独立知识照常发布。
2. **核验协议误拒与真实无效字段不同。** 旧 PDF 的115/115.0坐标、DOCX逐字 JSON 文本
   属于应用协议缺陷；已修复。之后 PDF 的 `path=["output",...]` 是模型给错根路径，
   原拒绝正确。新反馈不猜路径、不改变证据、不增加重试；后续首问/追问均机械完成。
3. **多余断言仍是质量问题。** PDF 最终回答主事实及左右图片对应正确，但仍夹带未请求
   的坐标及处理说明。旧 PPTX 追问先纠正文本框被称标题，随后仍把某批次的路由规则
   扩成 bin C 的所有用途限制，被有效核验拒绝；不重试同一无变化问题刷通过。
4. **标题翻译与生成自述。** 小文本先出现无依据“版本限制”，后出现 hold time 译为
   保压时间、规则例外译为诊断异常。最终 Continue 保留三条正确知识与原条件，已去掉
   页面导览。保存的误译核验控制仍被模型漏检，保留为未解决的鲁棒性反例。
5. **遗漏不等于导入失败。** DOCX 部分事实/图示候选遗漏，PDF两主题未过核验，均正常
   发布。旧 `02dd39e` DOCX产物中，局部表格留空的A行字段在另页完整保留，不能误报
   当时整个知识库缺该事实；v14后续的表格主题遗漏另列，不能沿用旧覆盖结论。
   XLSX 六行完整分布于多个知识页，页数/块数不能作为丢行判据。
