## 数据库存储修正

正式版统一使用 `.openkb/pageindex.db`：原版 PageIndex collection 负责建树、存储与原文读取，来源及解析绑定也保存在同一数据库。删除开发期导航 JSON 的读取、迁移和降级兼容。原件、解析及费用收据仍各自保留，不能代替数据库索引。

下文旧 6 小时真实模型实验冻结于 `7455f9f7` 之前，使用的是旧 JSON 索引制品；它们不能证明数据库改动的正确性或成本。数据库修正当时单独执行离线 SDK 与应用回归；上述追加小文档校准是另行授权的新实验，没有续跑或改写旧实验。

本次数据库离线检查覆盖 23 份原件的冻结原生解析，全部通过：139,922 个原生块、8,498 个索引节点、6,155,625 个原文字符逐块校验内容及位置；数据库包含 23 个 SDK 文档与 23 条来源绑定，SQLite 完整性检查为 `ok`。没有导航 JSON 制品，也没有网络或模型调用。该结果只验证数据库索引与原文回读，不等同于重新验证完整语义覆盖。

本次修正的完整回归：**1,977 passed、1 skipped（466.19 秒）**；ruff、格式及 mypy 检查通过。双轴复核没有剩余问题。新增回归覆盖数据库入库及实际消费、1,000 范围上限、损坏后的重建与复用、JSON 索引拒绝、SDK 中断恢复，以及配套目录、孤立绑定和受引用历史的清理保护。

## 已实现

导入先保存完整原生范围和不可变 PageIndex 索引，再编译知识。PDF 保留物理页，DOCX 保留段落及表格位置，XLSX 保留工作表、单元格与合并关系，PPTX 保留幻灯片、对象、备注与未解释内容边界。可选结构和摘要使用同一个有限执行额度；超限保留完整基本范围并明确降级。

问答和对话捕获同一发布版本的来源、解析和索引快照，按窗口回读原件并提供稳定引用。已发布索引缺失或损坏时明确失败，重建后才能再次使用。重建索引只切换匹配的已发布解析，不重写知识正文。

当前编译器按完整 `DocumentPlan` W/S/T、页面候选及关键审核请求复用；每个采用来源独立绑定原文位置及发布收据。请求内短 ID 和上下文复用不改变字面原文及范围归属。规划使用冻结证据、累积账本和有界协调，相同在途分析只有一个执行者；成功结果保存实际派发的输出上限。下文实验中出现的“事实提取→主题规划”计量均为 #52 前的历史路径，不能描述或验证当前 `DocumentPlan` 流程。

遗漏依赖、有限纠正和可选深度复核保留有效否定结论；草稿或缓存命中不能授权发布。更新、删除、人工修改与历史清理保留各自边界。更新和删除同时核对当前发布基线与来源自身发布收据；接受另一来源的链接清理不能转移人工内容归属，也不能授权以后覆盖。摘要的当前来源字段或标记被删除后，仍按可信历史内容检查。删除只撤回明确标记的知识区间。无法确认归属的摘要和自定义元数据保留，已修改或歧义区间使事务回滚。

## 验证方法

起点为 `b4c7ce311ad1c4d548920249b3a8006ce8159c7b`。B0 使用原实现；B1 为具备相同检索能力、未加入后续优化的冻结对照；候选另行冻结。修复后创建新快照，保留旧快照、失败和费用。成对实验期间不同时运行其他真实模型验证；后续 Office 吞吐检查单独标记并发条件。

用户指定的验证库仅用于读取连接配置。所有导入、恢复、问答、删除和清理在独立实验库或测试临时目录执行。总额度跨运行累计：100,000,000 tokens、10,000 请求、6 小时。最终29条运行记录已逐请求对账；实验最后结算发生于21,569.70秒（5小时59分29.70秒），后续只整理报告，无新增模型请求。模型用量包含输入、输出、重试、索引、核验及失败；未收到用量的请求保留 unknown。提供方缓存是输入 token 的子集，另列观察值，不从原始成本分母中扣除。

23 份冻结原件（13 PDF、5 DOCX、4 XLSX、1 PPTX）全部完成离线接入、原生解析和全范围精确回读。校准系列与独立验证系列分组隔离；12 条锚点直接从原件选取并冻结，独立于模型抽取。多段原件锚点允许引用同一原生对象中的有序完整范围。

真实问答分别检查数值、单位、主体、前提、否定、例外、跨资料归属及精确引用。成功保存知识并不自动通过这些项目。未解释的视觉内容不计入文本覆盖，本轮关闭 OCR 和视觉增强，其质量另行验收。

## 恢复与完整执行链

同源已完成复导和同版本已完成继续均为0请求、0 tokens；整轮耗时分别0.77秒和0.72秒。这验证的是已完成版本复用，不能代替未完成导入的恢复验收。

PDF-A跨来源运行重新绑定了全部4条可用导航分析；原先另外10次导航触及输出上限，未产生可共享结果。新成功导航改变688个事实单元中10个的导航语义，完整批次由266/235/174/13变为267/235/174/12。因此实际事实请求不等价，不能宣称相同完整事实请求已在真实案例证成零新增调用。本轮实际103请求、2,987,821 tokens全部保留。

PPTX-B首先在依赖检查前停止：7处原生未解释对象正确保留，但全量请求超出最大上下文，96个候选被应用保守标为unknown。不能写成模型判定这96个主题都依赖遗漏。修复将生成的HTML归属信息改为有序结构化片段，并将重复完整引用/上下文放入字典；离线逐项还原2603个原件对象、7条遗漏、全部事实及96份候选正文。实际生产提示下估算输入864,446 tokens；加131,072输出预留后可放入1,048,576上下文。容量可容纳不代表语义已通过。

修复也使输入超限仅扩大上下文，避免无谓扩大已足够的输出预留。实际依赖检查依旧经过原执行预算，原件及遗漏没有截断；核验配置及报文格式进入恢复键，改变核验模式后必须重新裁定。

这次规则版本更新和执行额度变化使PPTX部分缓存失效，导航重做后又改变了部分事实上下文。第一次继续在facts阶段停止：应用早期收据为已计量及在途预留2,750,266、7次未结算；最终传输结算为1,878,697已知tokens、0未知。两种记录分别保留。后续继续使用同一冻结代码，其费用与最初失败累计，不称为新冷导入。

DOCX-A候选在生成期间失去进程，未保存应用终态、发布或问答。最后可见进展3,243.46秒，673请求、14,661,514已知tokens；4次用量未知，673,284 tokens预留继续保留。停止后续排程后子进程仍运行了一段时间，真实退出原因和时刻未确证。原中间产物保持，后续使用同一冻结代码及配置独立继续，费用累计。
